\section{Proposed Method}
\label{sec:method}

We formulate VQA as conditional answer generation: given an image $I$ and a
Vietnamese question $q$, the model generates a short free-form answer
$y=(y_1,\dots,y_T)$. ViBridge-VQA starts from Vintern-1B~\cite{doan2024vintern1b},
keeps all of its pre-trained weights frozen, and trains only two small components:
a bridge between the vision encoder and the language decoder, and a low-rank
adapter inside the decoder. Fig.~\ref{fig:arch} contrasts this design with the
official fine-tuning recipe of Vintern-1B.

\subsection{Multi-Token Bridge}
\label{sec:bridge}

The vision encoder is InternViT-300M (24 layers, width 1024) and the language
decoder is Qwen2.5-0.5B-Instruct (24 layers, width 896); together they contain
about 0.94B parameters. Each image is resized to a single $336\times336$ view, which
InternViT splits into $24\times24$ patches of $14\times14$ pixels. The encoder
returns one 1024-dimensional vector per patch and a global \texttt{[CLS]} vector.
Vintern-1B discards the \texttt{[CLS]} vector and passes the patch vectors through
its projector, so the decoder receives one token per image region. ViBridge-VQA
takes a much cheaper route: its \emph{multi-token bridge} $g_\phi$ reads only the
\texttt{[CLS]} vector $v\in\mathbb{R}^{1024}$, which summarises the whole image, and
expands it into $k$ tokens in the decoder input space with two linear heads:
\begin{equation}
  g_\phi(v) = \big[\,W_a v + b_a;\ \mathrm{reshape}_{(k-1)\times 896}(W_e v + b_e)\,\big]
  \in \mathbb{R}^{k\times 896}.
  \label{eq:bridge}
\end{equation}
The first head produces an \emph{anchor} token, and the second produces $k-1$
complementary tokens that present the same global information to the frozen
decoder from different learned directions. With $k=8$, the bridge has 7.35M
parameters (0.78\% of the model). The $k$ tokens are placed before the embedded
question, and the decoder generates the answer autoregressively. We compare this
design with four larger or patch-based bridges in Section~\ref{sec:ablation}.

\subsection{Decoder Adaptation and Training}
\label{sec:training}

To let the frozen decoder make full use of the bridge tokens, we add a LoRA
module~\cite{hu2022lora} to the query, key, value and output projections of every
decoder layer. Each frozen weight $W_0\in\mathbb{R}^{d_\text{out}\times d_\text{in}}$
becomes
\begin{equation}
  W = W_0 + \tfrac{\alpha}{r}\,BA,\qquad B\in\mathbb{R}^{d_\text{out}\times r},\ A\in\mathbb{R}^{r\times d_\text{in}},
  \label{eq:lora}
\end{equation}
with rank $r=16$ and $\alpha=32$ (2.16M parameters, 0.23\%). The bridge, initialised
randomly, and the LoRA matrices are trained \emph{jointly} in a single run with the
answer cross-entropy
\begin{equation}
  \mathcal{L} = -\sum_{t=1}^{T} \log p\big(y_t \mid y_{<t},\, g_\phi(v),\, q\big),
  \label{eq:ce}
\end{equation}
so that 9.51M parameters (1.01\%) are trainable; the vision encoder and all
original decoder weights remain frozen. We refer to this full model as
\textbf{ViBridge-VQA}, and to the variant that trains the bridge alone with the
same objective as the \emph{bridge-only} model.
