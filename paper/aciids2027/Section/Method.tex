\section{Proposed Method}
\label{sec:method}

We formulate VQA as conditional answer generation: given an image $I$ and a
Vietnamese question $q$, the model generates a short free-form answer
$y=(y_1,\dots,y_T)$. ViBridge-VQA reuses the pre-trained components of
Vintern-1B~\cite{doan2024vintern1b} and trains only a bridge and a low-rank
adapter (Fig.~\ref{fig:arch}).

\subsection{Overall Architecture}

The vision encoder is InternViT-300M (24 layers, width 1024) and the language
decoder is Qwen2.5-0.5B-Instruct (24 layers, width 896); together they contain
about 0.94B parameters, and both stay frozen. Vintern-1B splits an image into
several $448\times448$ tiles and connects the encoder to the decoder through a
two-layer MLP projector. ViBridge-VQA instead encodes a \emph{single global view}
of the image and replaces the projector with a trainable bridge $g_\phi$. The
bridge maps the image representation to $k$ embeddings in the decoder input space,
which are placed before the embedded question; the decoder then generates the
answer autoregressively. The whole image is resized to $336\times336$ pixels, in
training and at test time.

\subsection{Multi-Token Bridge}

For a $336\times336$ view, InternViT splits the image into $24\times24$ patches of
$14\times14$ pixels and returns one 1024-dimensional vector per patch together with
a global \texttt{[CLS]} vector. Vintern-1B discards the \texttt{[CLS]} vector and
passes the patch vectors, merged $2\times2$, through its projector, so the decoder
receives one token per image region. The multi-token bridge takes the opposite,
much cheaper route. Let $v\in\mathbb{R}^{1024}$ denote the \texttt{[CLS]} vector. The multi-token bridge applies two linear heads to $v$. The first
produces an \emph{anchor} token that plays the role of the original single-vector
projection; the second produces $k-1$ complementary tokens:
\begin{equation}
  g_\phi(v) = \big[\,W_a v + b_a;\ \mathrm{reshape}_{(k-1)\times 896}(W_e v + b_e)\,\big]
  \in \mathbb{R}^{k\times 896}.
  \label{eq:bridge}
\end{equation}
With $k=8$, the bridge has 7.35M parameters (0.78\% of the model). All $k$ tokens
are linear functions of the same global vector, so the bridge is small and fast but
cannot convey information that $v$ does not contain, such as the position or number
of objects; Section~\ref{sec:reliance} examines this trade-off. To study the role of bridge capacity, we compare it with four
alternatives (Table~\ref{tab:bridges}): a \emph{Residual} bridge that produces one
token through a linear projection with a residual MLP, a \emph{Tile-Attention}
bridge in which 8 learned queries attend over the patch tokens, and a
\emph{Light} and a \emph{Full Q-Former} following BLIP-2~\cite{li2023blip2}, with
8 and 16 queries and 2 and 4 cross-attention layers.

\subsection{Training}

\paragraph{Objective.}
Both backbones stay frozen, and all trainable parameters are optimised with the
answer cross-entropy
\begin{equation}
  \mathcal{L} = -\sum_{t=1}^{T} \log p\big(y_t \mid y_{<t},\, g_\phi(v),\, q\big).
  \label{eq:ce}
\end{equation}

\paragraph{Bridge only.}
In the simplest configuration, only the bridge parameters $\phi$ are trained.

\paragraph{Bridge with decoder LoRA (ViBridge-VQA).}
In the full model, a LoRA module is added to the query, key, value and output
projections of every decoder layer. Each frozen weight
$W_0\in\mathbb{R}^{d_\text{out}\times d_\text{in}}$ becomes
\begin{equation}
  W = W_0 + \tfrac{\alpha}{r}\,BA,\qquad B\in\mathbb{R}^{d_\text{out}\times r},\ A\in\mathbb{R}^{r\times d_\text{in}},
  \label{eq:lora}
\end{equation}
with rank $r=16$ and $\alpha=32$ (2.16M parameters, 0.23\%). The bridge, initialised
randomly, and the LoRA matrices are trained \emph{jointly} in a single run with the
objective of Eq.~\ref{eq:ce}, so 9.51M parameters (1.01\%) are trainable. The
vision encoder and all original decoder weights remain frozen.
